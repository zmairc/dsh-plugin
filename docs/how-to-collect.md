# 怎么拿到第一批聊天记录

目标：**200 条**能跑通全流程的记录。不要一开始就导出十万条——先验证"像不像"，再上量。

全程在本机完成。原始记录不经过任何服务器。

## 一、先做三个决定

| 决定 | 建议 |
| --- | --- |
| 时间范围 | 取**最近 1–2 年**。人会变，2019 年的他和现在的他不是一个人 |
| 会话范围 | **只要一对一私聊**。群聊里混着几十个人的语气，会污染人设 |
| 留出比例 | 留 10% 不参与人设，专门用来评测。`ingest` 默认就是 0.1 |

## 二、方案 A：手动复制（推荐先走这条，200 条约 15 分钟）

### 微信 PC 端

1. 打开和 TA 的聊天窗口，往上滚到想开始的位置
2. **右键任意一条消息** → 菜单里选「多选」
3. 勾选连续的一段（**一次 20–30 条**，选太多会卡）
4. 右键 → 「复制」
5. 粘贴到 `personas/<名字>/transcript.txt`，换行，再重复下一段

复制出来的内容通常长这样，`ingest` 能直接认：

```
老王  2024-03-15 21:08:12
在吗

我  2024-03-15 21:09:01
嗯
```

### 微信手机端（PC 端没记录时）

长按消息 → 多选 → 勾选 → 「更多」→ 收藏。然后在 PC 端微信打开收藏，逐条复制粘贴。

### QQ

- **PC 端**：打开消息记录窗口 → `Ctrl+A` → 复制 → 粘贴
- **PC 端导出**：消息记录窗口 → 右键 → 「导出消息记录」→ 选 txt
- 手机端同微信，长按多选后转发到「我的电脑」

### 都会发生的损失

| 类型 | 会变成 | 影响 |
| --- | --- | --- |
| 图片 | `[图片]` | 内容丢失。想补就手动写一句「他发了一张猫」 |
| 表情包 | `[表情]` | **最可惜**。中文聊天的亲密感很大一部分在这里 |
| 语音 | `[语音]` | 内容全丢。高频语音只能自己回忆补录几句 |
| 撤回 | `[撤回了一条消息]` | 无所谓 |

表情包虽然复制不出图，但**位置和频率保留下来了**——`stats` 会告诉你"他有 18% 的消息是表情包"，这个信息本身就有用。

## 三、方案 B：工具导出（等到要处理上万条时再上）

| 平台 | 工具 | 说明 |
| --- | --- | --- |
| 微信 | [chatlog](https://github.com/sjzar/chatlog) | Go 写的，本地起 HTTP API 直接查聊天库，支持导出 JSON/CSV |
| QQ | [qq-chat-exporter](https://github.com/shuakami/qq-chat-exporter) | 解 NTQQ 数据库，导出 JSON |
| 抖音 | [douyin-chat-export](https://github.com/TeamBreakerr/douyin-chat-export) | 从网页版导出私信 |

导出后用 `--source wechat|qq|douyin` 标记来源。多个平台的记录**分别 ingest**，用同一个 `--persona` 名字，第二次会覆盖——需要合并的话把几次导出的 txt 拼成一个文件再跑。

工具会随平台更新失效。跑不通就退回方案 A。

## 四、挑哪 200 条

**不要随机挑。** 随机抽样几乎必然全是「哈哈」「在吗」「好的」，那是语气噪声不是人格。

按情境各挑 20–30 条：

| 情境 | 挑什么 | 为什么 |
| --- | --- | --- |
| 日常寒暄 | 「在吗」「干嘛呢」这类开场和收尾 | 决定闲聊的默认语域 |
| 情绪低落 | 他抱怨、示弱、说丧气话 | 决定他脆弱时的表达 |
| 安慰你 | 你难受时他怎么回 | 决定他的共情方式，最容易和通用 AI 拉开差距 |
| 吵架/别扭 | 争执、冷战、和解 | 冲突模式是最容易露馅的地方 |
| 分享安利 | 链接、视频、歌、游戏 | 决定他「安利」东西的语气 |
| 求助/给建议 | 你问他事，他给方案 | 决定他说理时的句式和长度 |
| 久别重逢 | 长时间没联系后的第一句 | 决定他的热络程度 |
| 深夜长聊 | 凌晨的消息 | 决定他放松状态下的句子长度和话题 |

这 8 类各 25 条就是 200 条。

## 五、粘完立刻自检

```bash
node src/cli/index.ts speakers --file personas/<名字>/transcript.txt
```

期望看到**两个说话人**，一个 `self` 一个 `friend`。然后：

```bash
node src/cli/index.ts ingest --file personas/<名字>/transcript.txt --persona <名字> --me 我 --friend 老王
```

看输出的「解析布局」和「说话人」两行。

### 常见失败

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 布局是 `blob` | 格式没认出来 | 把那 20 行样例发出来，加一种布局解析 |
| 只有一个说话人 | 复制时没带上昵称 | 换成「多选复制」而不是选中文字复制 |
| self 和 friend 反了 | `--me` 没配对 | 用 `--me <你的昵称>` 显式指定 |
| 多了 `other` | 混进了群聊消息 | 只从私聊窗口复制 |
| 消息数远少于预期 | 空行被合并了 | 检查头行是否「昵称 + 时间」在同一行 |
| 时间全是 2000 年 | 没解析到时间戳 | 手动方案 B 或补时间头行 |

## 六、验证完再上量

200 条跑通、`chat` 试过、觉得方向对了，再导出全量：

```bash
node src/cli/index.ts ingest --file wechat-full.txt --persona 老王 --me 我 --holdout 0.05
```

全量时 `stats` 才真正有统计意义（口头禅、表情包频率、回复节奏）。但**人设文件还是手写的**——全量数据不会自动变成好的 persona.md，它只是让你判断得更准。

## 七、隐私

- 原始 txt 和 `data/` 都在 `.gitignore` 里，不会误提交
- 要分享 persona pack 或截图前，跑 `ingest --redact` 打掉手机号、身份证、邮箱、链接
- 想连真实姓名一起打掉：先手动把 txt 里的名字替换成代号，再 ingest
